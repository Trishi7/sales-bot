## 2. The design

### 2.1 What "came from the dedicated sales folder" means on disk

Three pieces. All fail closed.

**(a) The tag: `NOTES_SOURCE_FOLDER` (NEW, default empty).** The operator declares the
one folder by name. It must appear verbatim inside `NOTES_SYNC_CMD`. This is the "tagged"
in Kushal's words, and it is what lets the server ship "not connected" without anyone
editing the server `.env` first (cause F).

**(b) The manifest: `STATE_DIR/notes_manifest.json`**, owned by the bot.
`{"version": 1, "source": "<NOTES_SOURCE_FOLDER>", "notes_dir": "<abs path>",
"written_at": "<iso>", "last_success": "<iso or null>", "files": ["<filename>", …]}`.
A file in `NOTES_DIR` is "from the sales folder" only if the manifest's `source` equals
the current `NOTES_SOURCE_FOLDER`, its `notes_dir` equals the resolved absolute
`NOTES_DIR`, and the filename is in `files`. No manifest, an unreadable one, or a
mismatch → nothing is from the folder. It lives in `STATE_DIR`, not `NOTES_DIR`, so a
mirror cannot delete it; if `state/` is wiped the next sync rebuilds it (everything is
quarantined and pulled again). `last_success` is carried forward from the previous
manifest when a run fails.

**(c) The sweep, run by the bot immediately before every sync.** Every regular file at
the top level of `NOTES_DIR` that is not in the current manifest is MOVED (never deleted)
to `NOTES_DIR/_quarantine/<YYYYMMDD-HHMMSS>/`. Because a changed `NOTES_SOURCE_FOLDER`
invalidates the whole manifest, the first sync after the source changes moves EVERY file
that was there (D6). One WARNING per sweep that moved anything
(`[notes] moved N file(s) that did not come from <folder> to <path> — nothing was deleted`),
and one `state.audit` event `notes_quarantined` with the count and the first 20 names. A
sweep that moves nothing logs nothing. Then the sync command runs. After the run —
success or failure — the manifest's `files` becomes the current top-level listing of
regular files: strays were swept first, so anything now on disk arrived from the
configured command.

**The quarantine is never read (D6).** `_candidate_files` (`notes.py:313-323`) already
lists only regular files at the top level of `NOTES_DIR`, so no subfolder is scanned.
Make that a stated guarantee: skip any entry named `_quarantine` explicitly, and never
recurse. `freshness()` (`notes.py:600`) uses the same function. A file at
`_quarantine/a/b/c.txt` must be invisible to `list_notes`, `read_note`, `freshness`,
`labels_on`, `sync_status` counts and the manifest. Consequence to document: notes must
sit at the TOP LEVEL of the Drive folder; subfolders are not read.

Why manifest AND mirror:
- Manifest + sweep handles the source CHANGING, the first run after this deploy (the 76
  stale files), and anything dropped into the folder by hand. It does not depend on the
  operator typing `sync` instead of `copy`.
- Mirror (`rclone sync`) handles a doc being REMOVED from the Drive folder later. The
  bot cannot detect that under `copy`.
- So: the bot enforces the manifest; `DEPLOY.md` prescribes `rclone sync`; and when the
  command contains ` copy ` rather than ` sync `, startup validation and the source
  status say so ("copies rather than mirrors: a note removed from the folder stays
  readable until it is moved out of NOTES_DIR by hand").

**The quarantine guard.** `rclone sync` deletes anything in the destination that is not
in the source, including `NOTES_DIR/_quarantine/`. rclone does not delete files that
match an `--exclude` filter. So `notes.sync_now` REFUSES to run a command that mirrors
(the word `rclone` and the word `sync` as tokens) unless the command also contains
`_quarantine`; the state is `misconfigured` and the log names the exact flag:
`--exclude "/_quarantine/**"`. Nothing the bot quarantined can then be deleted by the sync.

### 2.2 The states of the notes source

`notes.source_state()` returns exactly one of:

| state | when | readable notes | sentence (2.5) | `sources.py` status |
|---|---|---|---|---|
| `not_configured` | `NOTES_DIR`, `NOTES_SOURCE_FOLDER` or `NOTES_SYNC_CMD` is empty | none | not connected | AWAITING_ACCESS |
| `misconfigured` | the folder name is not inside the command; or a mirror command lacks `_quarantine` | none | not connected | AWAITING_ACCESS, detail names the fix |
| `unreachable` | configured, and: no manifest for this source yet; OR the manifest has zero files and (`last_success` is null or the last sync in this process failed) | none | unreachable | DEGRADED, detail carries the sync error and remedy |
| `empty` | manifest has zero files, `last_success` is set, the last sync in this process did not fail | none | folder empty | CONNECTED |
| `ok` | manifest has files | manifest files that pass 2.3 | none while ≥1 loads; folder-empty sentence when 0 load | CONNECTED, or DEGRADED while the sync is failing |

In `not_configured` and `misconfigured` the sync is never run and no file is moved.
Files already sitting in `NOTES_DIR` are simply not read. So deploying this to the server
with `.env` untouched changes nothing on disk and the bot says "Meeting notes aren't
connected to me yet."

`ok` while the sync is failing: the notes on disk are the sales folder's own last good
copy. They stay readable and the existing stale rule applies (`query_engine.py:196-197`).
See open question Q2.

### 2.3 The filter (deny by default)

A file is LOADED only if every one of these holds, checked in this order; each file is
counted in exactly one bucket:

1. it is in the manifest for the current source → else `not_from_folder`
2. it has a parseable date (unchanged rule, `notes.py:349-351`) → else `undated`
3. its title does not match the standup guard → else `excluded_standup`
4. `NOTES_REQUIRE_TITLE_TAGS` is empty, or the title carries one of the tags → else
   `missing_tag`

**Title matching, for both the guard and the tags.** Normalise title and pattern the
same way: `casefold()`; replace every run of non-alphanumeric characters (`[\W_]+`,
Unicode-aware, so `／`, `：`, `–`, `(`, `-` all count) with one space; strip. A pattern
matches when the normalised pattern appears in the normalised title on token boundaries
(pad both with one space and test substring).

| title | matches |
|---|---|
| `NFThing Kick-off ( AM Sync) – 2026／10／05 10：30 IST – Notes by Gemini` | `am sync`, `nfthing kick-off` |
| `NFThing Wrap-up ( PM Sync) – …` | `pm sync`, `nfthing wrap-up` |
| `NFThing Kickoff – …` | nothing (one token `kickoff`; not on the human's list) |
| `AM-Sync 2026-10-05`, `am  sync`, `AM_SYNC` | `am sync` |
| `Daily Stand-up`, `daily stand up` | `stand-up` |
| `AM Standup 2026-10-05` | `standup` |
| `Daily sync 2026-10-05` | `daily sync` |
| `Sales sync – 2026-10-05`, `Team sync …`, `Acme sync …` | nothing — LOADS (D2) |
| `PM Call – 2026／08／19 …` | nothing — loads IF it is in the sales folder |
| `Program sync …` | nothing (`program sync` ≠ `pm sync`; token boundary) |

**The standup guard = a built-in floor ∪ `NOTES_EXCLUDE_TITLE_PATTERNS`.**
Floor (a constant tuple in `notes.py`, not removable by config), exactly the seven of D2:
`am sync`, `pm sync`, `nfthing kick-off`, `nfthing wrap-up`, `standup`, `stand-up`,
`daily sync`.
`NOTES_EXCLUDE_TITLE_PATTERNS` ADDS to it. Its default becomes
`AM sync,PM sync,NFThing Kick-off,NFThing Wrap-up,standup,stand-up,daily sync`. Setting
it empty no longer means "load everything" (cause E). A bare `sync` is in neither.

Title only, never the body (unchanged, `notes.py:232-235`): a sales doc that quotes sync
content is allowed.

### 2.4 Not repeating "0 of 72 admitted, silently"

Operator-facing only. None of this reaches the channel.

- One INFO line per sync and per scan change:
  `[notes] source=<folder> state=<state> on_disk=N from_folder=A loaded=L standup=S missing_tag=T undated=U quarantined=Q`.
- A WARNING, once per distinct signature, when `from_folder > 0` and `loaded == 0`. It
  names the bucket that took everything and the variable to look at.
- `notes.sync_status()` returns the buckets; `sources.py` puts them in the status detail,
  so the startup log and `state/summary.json` show them.
- `config.validate()` logs at startup when `NOTES_REQUIRE_TITLE_TAGS` is set.

### 2.5 What each notes tool returns when there is nothing to read (D4)

Three module constants in `notes.py` (exact text, straight apostrophes):

```
SAY_NOT_CONNECTED = "Meeting notes aren't connected to me yet."
SAY_EMPTY         = "There are no sales meeting notes in the {folder} folder yet."
SAY_UNREACHABLE   = "I can't reach the sales notes folder right now, so I haven't checked the notes."
```

`notes.nothing_to_say() -> Optional[str]`: None when at least one note is loaded, else

| state | sentence |
|---|---|
| `not_configured`, `misconfigured` | `SAY_NOT_CONNECTED` |
| `unreachable` | `SAY_UNREACHABLE` |
| `empty`, and `ok` with `loaded == 0` | `SAY_EMPTY.format(folder=NOTES_SOURCE_FOLDER)` |

When it is not None, all four note-reading tools (`list_meeting_notes`,
`read_meeting_note`, `meeting_facts`, `todo_candidates`) return exactly this shape and
never raise:

```
{"enabled": <False for not_configured/misconfigured, else True>,
 "configured": <same>,
 "state": "<state>",
 "sales_notes_on_file": 0,
 "say": "<the sentence>",
 "do_not": "Reply with the sentence in 'say', word for word, as everything you say about "
           "meeting notes. Do not add a reason, a fix, a file name or a count. Do not "
           "answer from, or suggest, any other folder, document, sheet, channel or memory."}
```

No sync error text, no remedy, no bucket counts, no variable names and no file names are
in this result: anything in it can end up in the channel. The error and the counts live
in the log and the `sources.py` status detail (2.4).

`read_meeting_note` with `found=false` while other sales notes ARE loaded keeps today's
behaviour (say that note isn't on file, name the most recent sales note). When notes are
loaded, results keep their current keys and `notes_filter` carries only
`{"sales_notes_on_file": L, "last_successful_sync": …, "sync_degraded": …}`.

### 2.6 Routing (D5)

In `toolsets.py`:

- `GROUPS["notes"]` becomes `("list_meeting_notes", "read_meeting_note", "meeting_facts")`.
- NEW `GROUPS["todos"] = ("show_todos", "todo_candidates")`.
- NEW `GROUPS["today"] = ("show_todos",)` — the interim, and **the hook for NFT2-1063**,
  which adds its objectives tool to this tuple. Do not build that tool. `cadence_preview`
  and every notes tool stay OUT of this group.
- `today` is EXCLUSIVE: when the `today` pattern matches, `route()` returns `['today']`
  and nothing else, whatever other patterns also matched. This is what makes "show_todos
  only" true for "what do we need to do today on the Acme meeting?" as well. Implement
  as a module tuple `_EXCLUSIVE = ("today",)` checked at the end of `route()`.
- `_ROUTES["notes"]` narrows to meeting words:
  `\bmeetings?\b | \bmeeting\s+notes?\b | \bnotes?\s+(from|of|on|for)\b | \bminutes\b |
  \bcall\s+(with|notes)\b | \bdecid\w+ | \bdecisions?\b | \bon\s+hold\b |
  \baction\s+items?\s+from\b | came\s+out\s+of`.
  Removed: `standup`, `sync`, bare `notes?`, bare `action items?`, `to-?\s?dos?`,
  `what do i owe`.
- `_ROUTES["todos"]`: `\bto-?dos\b | \btodos?\b | \bto-?\s?do\s+(list|sheet|items?)\b |
  \baction\s+items?\b(?!\s+from) | what\s+do\s+i\s+owe`.
  Must NOT match the bare words "to do".
- `_ROUTES["today"]`:
  `\bwhat\s+(do|should|must)\s+(we|i)\s+(need\s+to\s+|have\s+to\s+)?do\b[^?.!\n]{0,30}\btoday\b |
  \bwhat(\s+is|'?s)\s+on\s+(for\s+)?today\b`.
  It must NOT match "objectives" (fixture step 4 belongs to NFT2-1063 and its routing is
  left exactly as it is: `[]`, the full set).
- Place `today` and `todos` directly after `notes` in `_ROUTES`.

### 2.7 To-do rows (D1)

`show_todos` hides, never edits, never deletes. The "Source meeting" cell is the string
`meetings.citation(note)` — "<meeting name>, <D Mon>" (`meetings.py:180-199`,
`todos.py:450`).

A row is SHOWN only by rule 3. Rules, in order:

1. Source meeting matches the standup guard (2.3 matching, applied to the cell text) →
   HIDDEN, reason `standup`. Holds whatever notes are on disk.
2. Source meeting blank → HIDDEN, reason `no_source_meeting`. (The literal reading of D1:
   a blank source "isn't an allowed sales note". See open question Q1 — this is the one
   line to flip if the human meant otherwise.)
3. Source meeting, normalised as in 2.3, equals the normalised citation of a currently
   allowed note; and, when the row's "Date raised" parses as an ISO date, that note's
   date equals it → SHOWN.
4. Anything else → HIDDEN, reason `source_not_an_allowed_note`.

When the notes source is not `ok` there are no allowed notes, so every row is hidden.

**Nothing about hidden rows reaches the model or the channel.** The tool result contains
only the shown rows; `open_total` and `shown` count VISIBLE open rows only; there is no
`hidden_total`, no reason, no note about hiding. In the `show_todos` note text
(`bot.py:2893-2900`) delete the sentence "An item with no source_meeting came from the
sheet by hand…".

**The log (operator-facing).** One INFO line per distinct (row numbers, reasons) set:
`[todos] hid N of M open row(s) whose source meeting is not an allowed sales note (standup=a, no_source_meeting=b, source_not_an_allowed_note=c)`
— DEBUG on repeats — plus one `state.audit("todo_rows_hidden", …)` per distinct set with
the sheet row numbers and reasons (no task text).

**The list for the test report.** NEW read-only script `tools/list_hidden_todos.py`
(builder writes it): reads the to-do sheet through `todos.read_rows` (never `ensure`,
never a write, never a sync), applies `todos.split_visible` to ALL rows (open and closed),
and prints a Markdown table: sheet row, `#`, To-do, Owner, Source meeting, Date raised,
Status, reason. When the sheet does not exist it prints
`The to-do sheet has not been created yet: 0 rows.` and exits 0. Exit 0 always unless
the sheet cannot be read (then print the error, exit 1).

`todo_candidates` needs no row filter: it reads through `meetings.action_items` →
`notes.list_notes`. It gains the 2.5 shape.

`todos.refresh` dedup keeps reading ALL rows (unfiltered), so a hidden row is never
re-appended. `refresh` itself is not changed and still has no caller.

**What live will say today (flag for the human, not a code question).** `TODO_SHEET_ID`
is blank and the status file says the sheet has not been created. `_show_todos`
(`bot.py:2852-2863`) then tries to create it and, failing that, tells the model to say
the sheet does not exist and give the fix. So until the to-do sheet exists, the live
answer to "what do we need to do today?" is about the to-do sheet not existing; once it
exists and is empty (or every row is hidden), the answer is the link and no open items.
Neither contains sync content. That is the consequence of D5 on today's server.
